# Porting plan: pi-ollama-cloud → ollama-cloud-copilot-chat

Source surveyed: https://github.com/fgrehm/pi-ollama-cloud (main, cloned to a
system temp dir on 2026-10-12; clone deleted after this plan was written).
It is a **Pi coding agent** extension for Ollama Cloud. This repo is a **VS Code
Copilot Chat** `LanguageModelChatProvider` for the same API, so every finding
below is judged for the VS Code provider context, not as a drop-in copy.

## Source feature inventory (what pi-ollama-cloud ships)

| Module | What it does |
| --- | --- |
| `models.ts` | Model discovery: `GET /v1/models` + `POST /api/show` with 8-way concurrency, strict response validation, `refreshModels` callback with restore/network phases, 4h refresh cooldown, persistence via pi's model store, empty-catalog and partial-failure guards |
| `thinking-levels.ts` + `reasoning.generated.ts` | Data-driven thinking levels: models.dev `reasoning_options` (generated table) → effort map; `OFF_NULL` override sets (gpt-oss family, minimax-m2.7 hide `off`); toggle-only models expose one level |
| `pricing.generated.ts` + `scripts/generate-pricing.ts` | Per-1M-token pricing scraped by regex from `ollama.com/pricing`; family `:tag` suffix matching; missing cached-input column normalized to input price; zero-price warnings for unmatched ids |
| `limits.generated.ts` + `scripts/generate-limits.ts` | Per-model max output tokens probed live: ascending `max_tokens` tiers + stop sequence, limit parsed from the API error text; single-model merge mode; indeterminate probes carry forward |
| `models.generated.ts` + `scripts/generate-models.ts` | Baked-in fallback catalog with full compat flags, stable serialization, `RETIRED_MODEL_IDS` exclusion |
| `web-tools.ts` + `cache.ts` | `ollama_web_search` (max_results, `expand=<index>` for full content from the cached search, refresh) and `ollama_web_fetch` (offset/full pagination, refresh); 15s timeout; disk cache 24h success / 15min negative TTL with entry/file size caps, eviction, 0600 perms, atomic writes, prototype-pollution guards; failure diagnostics with likely causes; auth/429/5xx/transport failures never negative-cached |
| `usage.ts` + `index.ts` | `/api/balance` (documented endpoint): window `remaining_percent`, `allowance_usd`/`balance_usd`, purchased credits, `period.until`; `/api/usage?range=24h|7d|30d` request histogram (10 req/min); footer status bar with 5-min timer + agent_end throttle + generation guard; `/ollama-cloud-usage` command |
| `config.ts` | Global + project JSON config with env overrides (`webTools`, `usageStatus`) |
| `utils.ts` | `fetchJsonWithTimeout` (linked timeout + external abort, status 0 = transport error), `concurrentMap`, `getContextLength` (`*.context_length` scan, 128k fallback), `httpError` status mapping, `envInt` |
| `models.ts` `buildCompat()` | Explicit per-flag OpenAI-compatibility table for pi's OpenAI transport |

## Prioritized recommendations

Ordered by value ÷ effort. R7, R2, and R3 are the cheap high-value wins; R1 and
R4 are the meaningful features; R5/R6 are quality-of-life.

### R1 (P2) — Add an `ollama-cloud_web-fetch` client tool

pi's `ollama_web_fetch` is the one user-visible capability we entirely lack.
The API surface: `POST https://ollama.com/api/web_fetch` with `{ url }`, key
auth, response `{ title, content, links[] }`.

- **Targets**: `src/transport/protocol.ts` (add `webFetch` endpoint),
  new `src/tools/registered/web-fetch-client.ts` + `web-fetch-tool.ts`
  mirroring the search pair, `src/tools/tool-name.ts` /
  `credential-binding.ts` (a second registered tool name),
  `src/extension.ts` (`vscode.lm.registerTool`),
  `package.json` (tool contribution if required by the search tool's pattern).
- **Keep from pi**: 3000-char slice + `offset`/`full` pagination with a
  "Continue: call … offset=N" hint; first call shows up to 10 links; failure
  diagnostics with likely causes (auth / rate limit / anti-bot wall / response
  shape), and never negative-caching auth/429/5xx/transport failures.
- **VS Code adaptations**: accept `vscode.CancellationToken` via the existing
  `createWebSearchRequestCancellation` pattern; render as
  `PreparedToolInvocation` message; the model drives pagination, so keep the
  "next offset" instruction in the text output.
- **Guardrail**: page content can embed credentials in query strings — the
  existing "never log prompts/responses" rule applies to cached page content
  too (see R6).

### R2 (P1) — Probe max output tokens in `refresh-models.mjs`

`/api/show` does not publish output limits; our `SNAPSHOT.maxOutputTokens`
values are hand-recorded and drift from reality (pi's probed table disagrees
with several of ours: e.g. glm-5.3 131072 vs 524288 probed, kimi-k3 131072 vs
524288, deepseek-v4.1-flash 384000 vs 393216, deepseek-v4-pro:0813 384000 vs
65536). VS Code uses `maxOutputTokens` for picker budgets, so wrong values are
user-visible.

- **Targets**: `scripts/refresh-models.mjs` (new probe phase), and on any
  applied change the changeset it already writes.
- **Mechanic (from `scripts/generate-limits.ts`)**: for each id, POST
  `/v1/chat/completions` with ascending `max_tokens` tiers
  (65536 → 524288) + `stop: ["OK"]`; a rejected request reports the exact
  limit via `maximum output tokens \((\d+)\)` in the error message. On an
  indeterminate probe (timeout/billing/rate limit) keep the existing snapshot
  value and warn — never drop a model's ceiling because one probe failed.
- **Adaptation**: write into `SNAPSHOT` lines the same way the script already
  rewrites `contextLength`/`capabilities` (keep `maxOutputTokens ≤
  contextLength` clamp behavior in `catalog.ts` untouched); report-only mode
  must list every disagreement before `--apply` touches anything.
- **Ops**: requires an `OLLAMA_API_KEY` in `.env` (already the script's
  convention); a slow model may need a 60s probe timeout.

### R3 (P1) — Enrich usage with the documented `/api/balance` endpoint

Our `src/usage/domain.ts` parses the undocumented `/api/usage` shape and can
only show percentage windows. pi's `usage.ts` consumes the documented
`GET /api/balance`, which adds: `allowance_usd` / `balance_usd` (a concrete
"$55.50 of $60.00 remaining"), purchased credits, and `period.until` (renewal
date).

- **Targets**: `src/transport/protocol.ts` (`balance` endpoint),
  `src/usage/domain.ts` (balance-response validators + merge into
  `OllamaUsageSnapshot` as new optional fields: `allowance`, `purchased`,
  `renewsAt`), `src/usage/presentation.ts` and `formatUsageRows` (new rows),
  `src/commands/commands.ts` (tooltip/QuickPick lines),
  `src/provider.ts::refreshUsage` (fetch both endpoints; each failure
  degrades independently).
- **Keep from pi**: strict validators (`remaining_percent` finite number,
  balance/allowance pairing), the plan-window fallback when no legacy windows
  exist (`plan ▕░░▏ N%` derived from balance/allowance).
- **Tests**: pure `node:test` for the balance validators and merge behavior
  (colocated `src/usage/domain.test.ts`), mirroring pi's `test/usage.test.ts`
  shape coverage (windows-only, allowance-only, purchased-only, junk input).

### R4 (P2) — Derive thinking profiles from models.dev `reasoning_options`

`options.ts` hand-maintains per-model profiles; a newly hosted model gets **no
picker at all** until someone edits the table. We already persist
`reasoningOptions` from models.dev (`metadata.ts`) but never consume them.
pi's `thinking-levels.ts` shows the mapping we can adopt:

- `toggle`-only → boolean on/off profile (our `BOOLEAN_PROFILE`).
- `effort` values `low/medium/high/xhigh|max|ultra` → graded profile; `max`
  and `ultra` both map to our `max` choice; our `off` maps to
  `reasoning_effort: "none"`.
- Hide `off` for the verified leakers: gpt-oss family, minimax-m2.7 (our
  family table already encodes exactly this).
- **Keep our extras**: the `default` (model-managed) choice and `on` (native
  policy) choices, `enumItemLabels`/`enumDescriptions`, and the rule that an
  empty/degenerate options list falls back to "no picker" rather than a wrong
  one (pi's equivalent of the minimax-m2.5 empty-table guard).
- **Targets**: `src/models/options.ts` (resolution order: hand-verified
  profile wins → models.dev-derived profile → none),
  `src/models/catalog.ts` (pass metadata into profile resolution if needed),
  `src/models/options.test.ts` (new cases: toggle-only, effort-only, empty
  options, unknown model).
- **Effort note**: `refresh-models.mjs` already flags thinking profiles as
  manual review; after this lands it can report models.dev-derived profiles
  as *proposed* pickers in the drift report.

### R5 (P3) — Drift-check the pricing table against the live pricing page

`pricing.ts` is hand-captured; `refresh-models.mjs` lists "pricing capture" as
manual review. pi's `generate-pricing.ts` proves the pricing page table is
server-rendered and regex-extractable.

- **Targets**: `scripts/refresh-models.mjs` (report-only phase; do **not**
  auto-apply).
- **Adaptation**: pi's `ROW_RE` assumes a single price row per family and no
  off-peak rows — our table intentionally carries DeepSeek peak **and**
  off-peak rows, so automation must stop at "report drift per row" and leave
  the peak/off-peak merge to a human. Keep pi's sanity check
  (`cacheRead > input ⇒ table layout changed`) and its
  `:tag`-family fallback logic as the matching rule.

### R6 (P3) — Cache web tool results + `expand` on search

pi saves an API call per repeated search/page (24h TTL; 15min negative TTL for
dead pages) and lets the model read a `[truncated]` search result in full via
`expand=<index>` at zero extra cost (the search API already returns full
content; we currently truncate to 12k chars and discard the rest).

- **Targets**: new `src/tools/registered/web-cache.ts` (in-memory Map +
  optional `context.storageUri` persistence if a later pass wants
  cross-reload hits), `web-search-client.ts` (return full results; add
  `expand` input; mark `[truncated]` like pi does), `web-search-tool.ts`
  (plumb cache + expand), and R1's fetch tool gets `offset`/`full`/`refresh`
  from day one.
- **Keep from pi**: never negative-cache auth/429/5xx/transport failures;
  `refresh` bypass flag; `# live query` / `# from cache` provenance footer;
  future-timestamp = stale guard.
- **Skip from pi**: the file-size-cap / eviction / 0600-perms machinery —
  only needed because pi persists full page content to a shared disk file; an
  in-memory VS Code session cache avoids that entire class of problems.

### R7 (P1) — Throttle post-request usage refreshes

`src/provider.ts` fires `void this.refreshUsage(...)` after **every** streamed
response, unthrottled. pi throttles its equivalent to one call per 5 minutes
(timer + agent_end share a cooldown, guarded against stale generations) and
notes the usage histogram endpoint is rate-limited (10 req/min). Under agent
loops this is our most likely source of 429 noise.

- **Targets**: `src/provider.ts` (per-credential `lastUsageRefreshAt` +
  min-interval check around the post-request refresh; manual
  `refreshUsage()` from the command stays always-allowed),
  `src/extension.ts` (optional 5-min timer while a model is active — reuse
  `usageStatus`).
- **Tests**: throttle logic as a pure function (colocated test) — given a
  `now()`, last-refresh timestamp, and interval, decide fetch/skip.
- **Polish (optional)**: pi colors its quota bar green/yellow/red at 60/80%;
  our status bar (`usage/presentation.ts`) could set
  `vscode.ThemeColor` error/warning backgrounds at the same thresholds.

## Explicit non-goals (do not port)

- **OpenAI-compat flag table** (`buildCompat`): we speak native
  `/api/chat` NDJSON; the flags are pi-transport trivia.
- **pi config files + env tuning** (`config.ts`, `PI_OLLAMA_*`): VS Code
  contributes configuration instead; add a setting only if a real need shows up.
- **pi's refreshModels/persistence plumbing**: replaced by the VS Code
  provider lifecycle + `onDidChangeLanguageModelChatInformation`.
- **Baked-in generated model list**: our `SNAPSHOT` + `refresh-models.mjs`
  drift pipeline is stronger for this repo (humanized names, ordering ranks,
  retirement dates) than a wholesale generated file.
- **Disk cache durability machinery** in `cache.ts` (caps, eviction, 0600,
  atomic rename): unnecessary for an in-memory VS Code tool cache (R6).
- **TUI renderers / status-bar components**: platform mismatch.
- **`getContextLength` fallback scan**: our `findContextLength` already
  prefers the architecture-scoped key and adds models.dev/snapshot fallbacks.

## Suggested follow-up order

1. R7 (throttle) + R2 (limit probing) + R3 (balance enrichment) — small,
   independent, each shippable with a patch changeset.
2. R1 (web fetch tool) — feature-sized; pair with a `node:test` round on the
   client parsing/formatting like the search client has.
3. R4 (data-driven thinking profiles) — behavioral change; gate behind the
   hand-verified table and cover with picker tests.
4. R5 + R6 — automation and caching polish.

Every code change lands with: colocated `node:test` coverage for parsing and
external-data behavior, a Changeset for user-visible behavior, and no
credentials or prompts/responses in logs.
